Campaign preview

Open /campaign or choose Campaign preview from the ship. Its Account shows the preview’s sync and safety copies. Original campaign returns to the original ship.

The preview has its own device database and /api/campaign/save endpoint under the same sign-in. Its save, backups and rescues have separate collections in cyber. The preview’s draft story and art load from the selected private release.

The save

Save v1: { version: 1, account: { uid, createdAt, updatedAt } }. Parsing is strict: unknown keys and newer versions are refused. Every change is a new version with its migration (v2 in CY9, v3 in CY10). Nothing carries over from any other game.

How it syncs

uma-rpg's rules (its D32, D45, D260), copied through uma-quest's hello app (cc42fd1). Boot opens the phone's save at once and syncs behind it; a change writes the phone, then syncs. Each round reads GET /api/save and decides:

PhoneServerStepWhy
No saveA saveAdoptA new phone opens the account's save
A saveEmptyPushThe first upload, revision 1
CleanNewer revisionAdoptAnother phone changed it
CleanSame revisionNothingUp to date
ChangedSame revisionPushIts changes go up
ChangedMoved onPush or AdoptThe save changed last wins whole (account.updatedAt); a tie keeps the phone's. An adopt keeps the phone's as a safety copy first
Started offline (revision 0)A saveAdoptAn account started offline never replaces the server's; it's kept as a safety copy

A stale push answers 409 with what's stored and the round decides again (three tries). A refused upload is kept in saveRescues before the error returns. Triggers: a change, the app returning to the foreground, the network coming back, Sync now.

The production-save rules

From uma-rpg's 2026-10-30 incident, where a hand grant wiped unsynced progress. They hold from CY3:

Never move save.account.updatedAt.
No server ever writes into a save.
A stale server date means stop and ask the owner.

Updates and deploys

  • Install: Safari → Share → Add to Home Screen. The icon is a neon ring with a gap, drawn in code.
  • Update: a waiting build shows Update ready · Restart; the shell is no-cache.
  • Deploy: every code push to main: lint, tests, the 180 KB check, then Cloud Run and Hosting, then health with the commit, /api/save 401 and uma-rpg still answering.
  • Local: pnpm api on :8121 (auth off) and pnpm web on :5214.
