Editable source and reproducible render

Return the native project, preferably a Blender .blend, with its dependencies and an executable batch render/export script or equivalent reproducible command. Record the application/version. Keep body, helmet, hands, tail and equipment as identifiable objects or collections. Reuse a named skeleton, family poses and material zones. Equipment stays independently replaceable in the source. Name anatomical hand contacts and Back/shoulder sockets; document the coordinate system.

Render every direction from the same model, rig and pose. Preserve asymmetric details by rotating the source, rather than reflecting its image. Keep the orthographic render camera, light, ground root and scale fixed. Begin at the board's 35-degree downward elevation, with no horizontal board rotation. Check the result in campaign before freezing the exporter profile.

Delivery sequence for this one character

  1. Standing source review. Return the editable model/rig/equipment, repeatable exporter, four equipped standing renders and phone-size/enlarged contact sheets. Development places this exact rig in the real campaign. Body-only views and object-ID/depth passes are generated QA aids when useful, rather than separate character paintings.
  2. First playable motion. From the same source, export a short planted walk loop, rifle ready/fire/recovery, a readable hit/guard reaction and Rig Break/reboot. Use a small set of clear key poses. Art supplies frame IDs, durations and holds; CY57 records the checked action mapping before animation expands. The game drives the actual pulses, hits and results.
  3. Integrated acceptance. Exercise Training, funded preparation and the next real boarding encounter. Check all directions, cover, selection, saved facing, interrupted playback, missing art and disabled-part behavior. Then prove a second loadout from the same reusable source.

Keep ordinary attack effects, warnings and numbers in game presentation. Character-specific signature rules and splashes remain CY61/CY62. Further identities and opponents follow the first equipped checkpoint and shared export profile.

Export and integration handoff

Return the native project, scripts, packed/linked resources, source and equipment versions/hashes, render settings, material/palette zones, frame sequences and a proposed atlas. A private manifest maps body/look, exact rig IDs, facing, action, frame index, timing, ground anchor, bounds and attachment/occlusion passes to source hashes and approval scope. CY57 supplies the executable schema; proposed fields remain labeled until implemented. Include a short regeneration command.

The first supported rig may use a fully equipped atlas rendered offline. This proves the real character with correct visibility before general modular composition is finished. Other rigs retain accurate existing fallbacks; that atlas must never silently represent a different loadout. Keep reusable 3D components. CY57 then selects and measures reusable render passes/composition or supported pre-rendered variants, with a bounded encounter cache and explicit coverage. Export only the combinations needed for reviewed campaign cohorts.

Store projects, images, named cast, prompts, approvals and screenshots in ignored private content. Record design approval, model review, pixel-export review, valid runtime import, Platform publication and campaign integration separately. Preserve older source approvals and pinned handoffs.
