# CY76 Development · Publish and load approved crew sprite bundles

## Outcome

Connect the regular Art publishing flow to the campaign's deployed bundle reader. Prove two
playable recruits using the same compositor on the real Training Deck and a campaign ground
mission. Start independently of the story restructure. Use the existing CY57 board contract.

The hosted pointer has zero combat sprite bundles. The game already reads pinned bundles and can
stage a scoped bundle through `scripts/art/combat-sprites.ts`. The generic Art event still
resolves image assets and needs a bundle-specific path.

## Implementation

1. Accept a producer receipt with canonical outfit, manifest version and status, exact approval
   hash, page and placements pins, source index revision and destination campaign scope.
   Keep local fitted previews and the composited game export tied by source hashes. Reuse the
   existing combat manifest parser. Verify all files before building the release and verify
   the immutable Platform objects before campaign selection.
2. Route the normal Cyberpunk sprite event and its scoped actor selection through the existing
   immutable bundle publisher. Keep the prior index available until its candidate is written
   and verified. Carry the selected campaign's exact files, assets and other sprite references
   forward. Journal outcomes for stages, stale generation, retries, same-hash no-ops,
   withdrawals and rollback. Preserve existing image-category events and other games' paths.
3. Preflight the two staged recruits. Validate stable outfit identity, S/W/N/E, foot registration,
   active equipment layers, named grip/mount points, clip events and shared-family treatment.
   Connect the second source's compositor bindings to the game contract where parsed fields
   or expected clips differ. Use the real deploy input and a two-unit Training fixture where
   two-party mechanics need it. Produce a content-only candidate for the reviewed cohort.
4. Verify that both assets are resolved for independently frozen rigs within one battle.
   Measure request/decode count, decoded image and texture footprint, live frame behavior,
   and cleanup after leaving or retrying. Share pages only by content hash and keep the current
   standee fallback safe when a bundle is absent, invalid or missing a specific supported pose.

## Acceptance

- Test dry run, draft refusal, corrupt/missing page, approval or identity mismatch, two different
  releases, broken source readback, stale pointer, interrupted Platform/game stages, repeat
  publish and rollback. Verify game inputs, saves and unrelated release refs are preserved.
- Run the local and hosted-approved release path for both recruits. Verify their different
  frozen rigs, equipped mount cues, exact splash independence, resume and an actual boarding
  fitting. Keep four-facing captures and the release receipt. Preserve prior outfit and version
  records, plus the physical iPhone check under CY37.
