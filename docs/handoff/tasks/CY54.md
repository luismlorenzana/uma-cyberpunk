# CY54 Development · Ship order cinematics with talking profiles

## Outcome and dependencies

Present the Captain's real ship orders through pilot-suit splashes, talking profiles, dialogue and
readable ship effects. Reuse the first CY48 presentation checkpoint and coordinate the room plates
from CY51. Read the [delivery contract](../../design/campaign-art-delivery.md), [CY55 Art](CY55.md),
[CY56 Story](CY56.md), `ShipCommandScreen.tsx` and the domain ship-command reducer.

## Implementation

1. With Story and Art, define additive validated bindings for the actor, approved suit/splash/profile,
   action/result cue, enemy communication and effects. Include neutral fallback, portrait expressions,
   safe areas and whether a shot is full CG or a pose over a shared station plate. Separate the
   presentation key from the numeric command rules. Document the implemented fixture and format.
2. Build playback from the saved resolved command result and frozen input. Capture the acting officer
   and relevant target/outcome when resolving the order; later reassignment or an art release must
   not change who performed it. The sequence can show order, response, action and result. Fast/skip
   reduces presentation time while leaving the same readable result and log.
3. Persist the committed order before playback. Reload must resume/show its result without issuing
   another command or charging a second launch. A compatible pack swap resolves the same event with
   the current art binding; missing art falls back to the officer/profile and textual result.
4. Support talking profiles over the splash using the CY48 contract. Pilot, shields, gunnery and
   engineering have role-aware lines and effects. Reuse a character's primary operating pose across
   station plates where it fits. Enemy calls identify the authored boss and current role, with the
   matching approved pilot-suit portrait and existing expression vocabulary.
5. Integrate the First Watch escort and first occupied approach with draft art/lines immediately.
   Cover shield allocation, guns, fighter interception/strike, power redirection, targeted emitter,
   protected objective damage, loss and victory as supported by those encounters. Never depict an
   emitter disabled or a convoy safe before the actual result says so.
6. Expand by the shared encounter registry to local defenses, fleet contributions and the later works
   ferry and hired tender. Preserve objective names, independent command backdrop/cutout bindings,
   free retry and original frozen battle inputs. Keep primary controls and integrity meters visible
   or return them without losing the player decision state.

## Verification

Use meaningful reducer/playback tests for commit-once, reloaded outcomes, old inputs, missing bindings,
actor reassignment, fast/skip and a release swap. Play the actual paid escort and occupied approach,
one loss/free retry, both boarding entries and a later-tier protected-craft encounter. Confirm the
order log and cinematic agree on actor, target, shields, damage and objective outcome.

At 844 × 390 inspect profile expressions, text, target visibility, safe areas and skipped results.
Keep effects lazy and device-friendly; measure memory/frame behavior during consecutive orders.
Run implementation lint, tests and build. Carry actual installed-device review into CY37.

## Done when

The command registry is covered by working cinematic bindings or explicit draft fallbacks, representative
real missions pass, and no playback path mutates a resolved order. CY55/CY56 exports and outstanding
authoring are recorded against the same candidate release. Delete this packet with its Done row.
