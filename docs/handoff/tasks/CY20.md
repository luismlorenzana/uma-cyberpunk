# CY20 Campaign foundation

## Why

The opening needs a real campaign entry, reliable local tooling and an isolated save before the first script can be played.

## Context

Read the [rework brief](../../design/campaign-rework.md), [app architecture](../../game/architecture.md), `apps/web/src/save/`, `apps/api/src/save/`, and `packages/domain/src/save/`. The intake found missing or stale private dependencies, line-ending comparisons in generated documentation tests, and a Windows story test that launches the Unix tsx shim.

## Decisions made

Use the current app, owner sign-in, save transport, private master data and tactics package. The rework starts fresh in a distinct campaign save locally and on the server, including its backups and restores. Existing campaign data remains accessible through its original identity.

## Do

- Restore a reproducible install from the lockfile. Verify lint, tests, build and the 180 KB initial JavaScript budget. Fix Windows-specific failures at their source if they reproduce with the pinned dependencies.
- Wire the new campaign entry and persistence identity through boot, local storage, remote reads and writes, sync, restore and rescue. Reuse existing reconciliation behavior. Exercise both identities with the same signed-in account.
- Define a versioned campaign pack with stable scene, quest, encounter and asset references. Validate the pack and load it through the private content seam. Give the story and art contributors an exact contract and an in-game preview entry.
- Author a playable draft preview pack with an invented recruit, a short exchange, one choice, a saved consequence and placeholder portraits and backdrop. Use it to exercise the same contract and loader as approved content.
- Document and run the release path from source validation and reference checks through packing and private preview publication to loading in the app. Reuse the private content seam and hash-addressed files. Publish a second preview with changed dialogue and an image under the same IDs, then verify update detection, integrity checks, save continuity, and recovery to the first release.
- With story and art, establish the opening quest brief and the private selection of the first recruit and counterpart. Reserve a clue slot only if the story can make it belong in the opening.

## Done when

A fresh preview loads its selected pack and creates its own save. Writes and restores in either campaign cannot alter the other's data. The validation paths identify bad references with a source path. Both baseline preview versions run through the real app. The revised lines and image load under the same IDs, a save from the first release can continue, and the previous pack can be selected again. CI uses invented fixtures and the source content guard passes.

## Deliver

Record the campaign and pack identity decisions. Include a short author guide with the supported story and asset fields, example source shapes, preview publication steps and release recovery. Link the opening brief from CY21 and CY22. Follow the repo PR workflow, delete this packet when complete and add its Done row.
